# 系统设置与版本更新

适用于 v2。登录管理后台，点击左侧「系统设置」。网站运营配置保存在网站数据库中，重新部署不会覆盖；服务器密钥仍只保存在私密部署配置中。

## 1. 修改网站名称和图片

1. 打开「网站资料」。
2. 填写网站名称、站点介绍、联系邮箱和页脚说明。
3. 点击 Logo 或浏览器小图标的文件选择框，从电脑选择 PNG、JPEG、WebP，单张不超过2MB。
4. 点击「保存网站资料」。
5. 看到保存成功后，打开前台确认新名称和图片。后台、登录页也会使用新资料，不需要重启服务器。

首页小标语和大标题也在「网站资料」修改。大标题回车换行，最多4行、180字；小标语最长60字。留空保存会隐藏对应文案。首页已移除原有长说明段落，但保留大标题和资源统计；「站点介绍」仍用于页面描述，不作为首页长段落展示。文案按纯文本显示，不执行 HTML。

图片会重新编码成 PNG 并保存到网站运行数据卷中，不上传网盘或 R2。Logo 与图书封面是不同的文件；书籍封面仍可使用 R2。勾选「恢复默认图标」即可取消自定义图片，旧图片不会立即删除，以免缓存中的页面出现坏图。

## 2. 修改管理员账号和密码

1. 打开「账号安全」。
2. 修改管理员账号或显示名称，输入当前密码。
3. 要改密码时填写两次新密码，长度12—128个字符；不改密码则留空。
4. 点击「保存并重新登录」。
5. 回到登录页，使用修改后的账号和密码登录。

修改账号或密码后，其他设备上的旧后台登录也会失效。桌面软件的专用同步授权保持不变，需要撤销时前往「桌面同步」。

如果忘记密码，仍可在服务器项目目录执行 `sudo bash deploy.sh password`。只有一个管理员时会识别其当前账号，不会因为曾改名而重新创建默认 admin。多个管理员须由维护者明确指定账号；不要删除数据库或修改初始密码来重置已有账号。

## 3. 修改封面图片域名

1. 打开「系统设置 → 桌面同步」。
2. 每行填写一个封面域名，例如 `images.example.com`，不要填写协议、端口或文件路径。
3. 点击「保存白名单」。
4. 回到桌面软件重新执行同步预检。

留空并保存表示禁止通过桌面同步引入任何远程封面域名。域名限制在预检和最终导入时都会检查。修改白名单不会删除已有图书或更换网站编号。

左侧「桌面同步」可生成/撤销设备授权，并查看最近20个同步批次。服务器版不再提供「云盘上传」；电子书仍由桌面软件上传，旧上传记录不删除，桌面夸克环境不改变。

## 4. 绑定一个或多个域名

支持一个主域名、最多20个填写的别名，切换时另外保留旧主域名作为访问入口。所有别名永久跳转到主域名，不是多个独立网站。

1. 在域名服务商处将新域名解析到这台服务器，确保80/443端口开放。
2. 打开「系统设置 → 域名管理」。
3. 填写主域名和别名，不带 `https://`，别名每行一个。
4. 可以先点「仅保存草稿」。看到「尚未更改实际访问地址」，表示网站地址还没切换。
5. 准备应用时输入当前管理员密码，勾选确认，点击「验证并应用域名」。
6. 看到「任务已提交」后，去「维护记录」刷新查看结果。
7. 只有显示「域名已生效」才算完成；打开新地址并重新登录，修改桌面软件的网站地址。

系统会验证公网解析、有效 HTTPS 证书，并检查新域名确实指向本站。验证失败保留原配置；不要反复切换以免触发证书申请限制。不会替你购买域名或修改域名服务商的 DNS。

旧域名必须继续由自己持有并维持解析，才能正常跳转。切换后的图书路径仍是固定 ID，不因书名改变。

## 5. 检查并选择版本更新

1. 打开「系统维护」，点击「检查正式版本」。
2. 查看当前版本、最新版本和更新说明。
3. 不需要更新时直接离开页面。仅检查版本不会升级或重启网站。
4. 要更新时先暂停桌面同步，避开访问高峰，输入当前密码并勾选维护确认。
5. 点击「备份并更新到…」。维护期间网站会显示维护提示，后台也可能暂时无法访问。
6. 等待后刷新页面，确认维护记录显示成功，并检查前台与图书数据。

仅接受固定官方仓库 `onlylm/shuku` 的正式 Releases（如 `v2.0.0`），不跟随每次 Git 提交、分支或预发布版本。开始升级前再次核验完整提交编号和版本文件；服务器源码有未提交改动时会拒绝升级。

升级流程：核验版本 → 停止对外写入 → 完整备份 → 切换到确认的源码版本 → 构建与迁移 → 验证 HTTPS 和主要页面 → 恢复访问。

备份失败不会升级。升级失败时尝试将源码、应用镜像和数据库/文件恢复到升级前状态；恢复校验也失败则保持维护状态并阻止新任务，必须由维护者处理。断电或进程被强制结束后不会盲目重跑升级。不能保证所有服务器故障都能无人值守恢复。

## 6. 备份与维护服务

「只创建备份」不更新程序。备份包含数据库、运行数据（含 Logo）、本地封面与部署配置，不包含 R2 对象或网盘电子书。维护记录显示服务器上的备份目录；应另存到服务器之外的安全位置。备份含敏感信息，不提供公开下载，不上传 GitHub。

使用 v2 的 `sudo bash deploy.sh` 部署成功后，会在支持 systemd 的 Linux 服务器上安装专用维护服务。首次由旧版升级到 v2 仍需服务器维护者完成一次部署，旧版后台不会凭空出现新按钮。

网页只提交有限格式的任务，不持有 Docker socket，不执行任意命令。服务每15秒左右检查一次**管理员已确认**的任务；不会定时自动升级。

没有维护服务、服务离线或另有任务时，域名应用、备份和升级按钮禁用。网站资料、账号、封面白名单、域名草稿和手动检查版本仍可用。非 systemd 系统需维护者安排 `sudo bash deploy.sh maintenance` 的受控执行，不能直接给网站进程管理员权限。

服务器维护者排查：

```bash
systemctl list-timers 'shuku-maintenance-*'
sudo journalctl -u 'shuku-maintenance-*' --since '1 hour ago'
sudo bash deploy.sh status
```

完整日志只供维护者查看，不要公开分享。`deploy/control/status/active.json` 表示有正在执行或中断待处理的维护任务；不能直接删除该文件来强行再次升级。确认数据库、源码和镜像一致、网站恢复正常后，再由维护者解除中断状态。

维护中断时，同目录的 `recovery-任务编号.json` 保存必要的恢复线索（只允许服务器 root 读取）；域名恢复资料可能包含部署密钥，严禁上传或公开。恢复升级前数据库时，会先清理本网站数据库中的失败迁移残留表，再导入已校验的完整备份，不影响其他数据库。

## 7. 发布者须知

要向安装者提供正式更新，需要先完成测试，将 `VERSION` 改成目标正式版本（例如 `2.0.0`），再以同一提交创建 `v2.0.0` 标签并发布非预发布的 GitHub Release，写清变化、停站时间和迁移注意事项。不要重写已发布标签。

`2.0.0-dev` 仅表示本地开发版，不等于正式发布或线上升级完成。提交文档和源码本身不会触发任何安装者的自动更新。
