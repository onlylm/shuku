# 网站分类与同步升级说明

v2 调整网站的数据规则和后台操作，沿用 FastAPI、MySQL/SQLite、Docker + Caddy 部署方式。升级不会自动更换域名或修改桌面夸克连接器及账号环境。

## 1. v2 的主要变化

| 场景 | 新行为 |
| --- | --- |
| 电脑同步图书 | 优先使用内部系统编号 `BK_…` 对应网站资源；改名不会新建第二本书 |
| 相同 ISBN 或相似书名 | 仅作为未绑定图书的候选，由用户确认，不自动合并版本 |
| 旧修订同步 | 拒绝旧修订；同一修订编号但内容不同也拒绝 |
| 分类同步 | 人工来源映射优先；已知来源大类自动归入固定八大类，确认提交时才创建对应二级目录 |
| 分类未匹配 | 保留来源名称和资料，存为草稿并提示处理；不会自动往导航里创建分类 |
| 网站人工审核 | 可保护书名、作者、出版社、简介、封面、版权及分类；桌面覆盖选项不能绕过保护 |
| 书名修改 | 固定使用 `/book/id/{网站图书ID}`；保留原网站编号和系统绑定编号，旧书名网址 301 跳转 |
| 链接失效 | 隐藏无效入口，保留已发布书籍资料页、分类列表、搜索结果及站点地图中的书籍网址 |
| 新发布 | 版权类别、来源说明、分类路径必须通过检查；作者/出版社中的明显广告或联系方式需要处理 |
| 不通过检查 | 资料保存为草稿，提示具体原因，不假装发布成功 |

版权默认值已改为“待核验”。填写“已授权”和来源文字不是法律核验的替代；操作人仍需确认真实授权。作者、出版社和简介缺失不会被自动猜写，也暂不作为本轮的硬性发布条件。

后台手动发布合格书籍资料页可以没有网盘入口；桌面自动发布仍要求本次网盘检测通过。这两个操作刻意区分。

### v2：固定 ID 详情页地址

详情页统一使用 `/book/id/123`，数字是网站数据库中该书已有的 ID，不是重新生成的编号，也不是桌面 `BK_…` 或网站 `BK-…` 编码。

- 修改书名、作者或分类不会改变 ID 地址。
- 旧 `/book/书名别名` 保留，按旧别名精确定位，再一次 301 跳转到对应 ID 页；已删除、归档或草稿书籍返回 404。
- `/book/1984` 仍按原书名别名查找，不会被当成编号1984。数字 ID 专用 `/book/id/` 前缀。
- 书卡、搜索结果、后台“查看前台”、规范网址标记（canonical）、Book 结构化数据和站点地图都使用 ID 地址。
- JSON 搜索接口新增 `detail_url`；原 `slug` 字段保留兼容。
- 新旧地址支持 HEAD 检查；跳转和 HEAD 不重复计入浏览量。
- SQLite 升级后与 MySQL 一样不复用已删除图书的 ID；不重排已有编号。永久删除后重新导入是新记录、新 ID，不等于恢复原书。

旧书名别名仅能兼容数据库中仍保存的地址。若更早版本曾经改过别名、且旧值没有留存，需要根据历史记录另补映射，不能凭空恢复。

## 2. 分类怎样处理

打开后台 **分类管理 → 分类映射与发布检查**。

### 升级自动整理与固定导航

执行正常更新命令后，迁移会自动运行一次，无需重新上传电子书：

- 顶部固定为文学小说、历史传记、哲学社科、经济管理、科学技术、艺术设计、生活成长、教育少儿。新增图书或二级分类不会增加顶部项目。
- 已知旧大类按完整分类名映射；细分类移到对应大类之下。同名二级分类归并，旧网址保留或301跳转。不按书名、ISBN猜测内容。
- 补齐图书与新大类的关联；保留图书编号、原始来源分类、作者、简介、版权、发布状态、文件记录及分享链接。不会给全部书目加人工锁。
- 未识别、自定义或冲突分类保留供人工检查；已隐藏内容不自动重新显示，已有人工来源映射不覆盖。后台「分类管理」显示升级整理结果及待检查项。
- 重复更新、重启不会再次覆盖整理后的人工调整。该数据迁移不能靠回退程序版本自动撤销，完整撤回请恢复升级前备份。

例如桌面传来「计算机互联网 / 人工智能」，自动进入「科学技术 / 人工智能」。预检只展示计划，不创建分类；确认同步时才建立缺少的二级目录。没有明确大类的图书仍保存为待检查草稿，不随意归类。

点击顶部大类后显示二级导航和“全部”入口；二级导航只显示含已发布图书的分类。大类列表汇总下属图书并去重。后台移动二级目录时，会同时修正关联图书的上级归属。

### 来源分类与网站名称不同

1. 填写“来源一级分类”和“来源二级分类”。
2. 选择现有网站目标分类。如果选了二级分类，其一级分类会一起使用。
3. 点击“保存映射”。例如来源“历史文化 / 中国历史”可以映射到网站“历史传记 / 中国史”。
4. 在桌面重新预检、同步对应图书。已保存的旧预检若被提示过期，需要重新生成，不要反复提交旧批次。

二级留空只匹配来源没有二级的情况，不会把所有未认识的子类吞进该一级分类。保存映射本身不批量改动旧图书。已保护的图书需要直接在网站编辑，或先明确解除保护后再同步。

### 网站已有重复分类

1. 先完成站点备份。
2. 在同一页选择“需要合并的旧分类”和“保留的目标分类”。
3. 点击“只预览影响，不修改数据”，核对图书数量和修改前后分类。
4. 确认无误再点击确认合并。

有下级的旧分类先逐个合并下级，再处理一级。合并后旧分类不删除，只隐藏并保留永久跳转；图书网址不会变。此次分类修改会保护对应图书，防止旧本地分类重新写回。

如果原书存在其他分类分支，合并只处理选中的旧分支，保留其他分支并通过发布检查提示继续整理，不盲目清空。合并操作在 `admin_operation_logs` 留存受影响图书及修改前后分类、保护状态、映射和旧分类信息。

升级仅应用固定八大类中列明的完整名称规则；规则以外的近义类别仍由运营者确认，不做模糊猜测。

## 3. 人工审核保护和发布检查

在 **资源管理 → 编辑图书**：

- “本次保存后保护人工审核资料”默认勾选；页面另有当前保护状态。
- 若确实需要恢复桌面自动修改，取消勾选并保存。下次人工编辑保存时可再次保护。
- 保护状态下，桌面仍能添加分享链接，不会覆盖已审核的书目和分类。
- 分类使用两级联动下拉菜单：先选一级，再选对应二级（可不选）。不再展开全部分类复选框；已有分类自动带入，切换一级会清空不对应的二级，保存后替换原分类路径。旧数据若存在多分支、隐藏或已合并分类，默认保留并提示确认，明确选择新路径后才替换。
- 点击“保存并发布”后，若检查不通过，资料会存为草稿，提示待处理原因。

**分类映射与发布检查**页面会列出旧图书待处理问题。仅打开检查页不会自动下架旧图书；后续新发布或资料更新会执行检查。

## 4. 表格导入的变化

- 普通带分享链接的导入，新建图书默认草稿，不再默认为“已获授权、已发布”。
- 元数据补全支持“系统编号”或 `book_id` 列。有编号时只按该编号查找；编号不存在不会退回书名匹配，避免错填另一版本。
- 不带编号仍保留传统匹配供人工确认。同一 ISBN 存在多条记录时不自动选其中一本。
- 元数据分类不再模糊匹配或自动新建，也不再追加分类。
- 网站资料已经保护，或预检后已被修改时，不覆盖；请解除保护或重新预检。
- 成功的人工作业会保护该书资料。未确认的分类不会被自动套用。

## 5. 升级到服务器

本说明随源码交付。**只有本轮源码已经提交并推送到你的 GitHub 仓库后，服务器更新才能拿到这些修改。**本地完成修改不表示线上已经升级。

下文使用 `/root/ebook-site` 作为示例，若项目安装在别处，替换此目录。

1. 暂停桌面向网站同步，登录服务器并进入项目：

   ```sh
   cd /root/ebook-site
   sudo bash deploy.sh backup
   ```

   看到备份完成后，保存终端显示的完整备份目录。备份含数据库、封面和运行数据；不要把备份或 `deploy/.env` 上传 GitHub。

2. 确认新源码已推送后执行：

   ```sh
   sudo bash deploy.sh update
   ```

   现有更新流程会再次备份、拉取源码、构建网站并启动。网站启动时自动执行数据库迁移。若提示服务器有未提交源码修改，应先人工处理，不能强制覆盖。

3. 检查运行状态：

   ```sh
   sudo bash deploy.sh status
   sudo bash deploy.sh check
   ```

   容器应处于正常运行状态，站点检查应通过。

4. 进入后台确认出现“分类映射与发布检查”，先用一两本测试，再恢复大批量同步。

新数据库版本为 `20260831_0006`：包含前一版 `20260831_0005` 的来源映射、分类跳转及审核保护字段，并为 SQLite 开启资源 ID 不复用保证；MySQL 原有自增主键保持不变。迁移不自动改书名、旧别名、内部编号、版权状态、分类关系或发布状态。网址改用 ID 是路由变化，不需要批量重写图书记录。有明确后台单书编辑审计记录的旧图书会开启保护。

### 可选：只读完整检查

在服务器项目目录执行：

```sh
docker compose --project-directory deploy --env-file deploy/.env -f deploy/compose.yml exec -T web python -m scripts.catalog_audit
```

输出 `"changed": false` 表示未修改数据。报告包含重名分类、未映射图书和发布检查问题，不输出密钥。

高级维护也可使用 `python -m scripts.catalog_audit --source-id 旧编号 --target-id 目标编号` 获取合并预览；只有再明确传入 `--apply 本次预览的fingerprint` 才会执行合并。一般运营建议直接使用后台预览页面。

## 6. 验收与恢复

升级后建议逐项确认：

1. 打开旧书名网址，应跳转到 `/book/id/数字`。修改书名后该 ID 地址不变，旧书名网址仍可跳转到它。
2. 同步相同系统编号，资源总数不因改名增加。
3. 更换分类并同步后，不再同时挂着旧分类。
4. 保护一本书，桌面选择覆盖也不能改写审核后的作者、简介和分类。
5. 上传一个未知分类，不能偷偷创建新导航分类，应保留草稿及待处理原因。
6. 临时隐藏一本已发布书的网盘入口，资料页仍打开，下载区域提示暂无入口；重新启用入口后恢复下载按钮。
7. 版权待核验或作者含广告的测试资料，不能自动发布。

遇到问题先暂停同步、检查日志，不要删除数据库卷。分类合并没有“一键撤销”按钮；优先查看审计记录人工反向调整。如必须整站恢复，用之前完整备份：

```sh
sudo bash deploy.sh restore /root/ebook-site/backups/实际备份目录
```

这是整站数据恢复，会覆盖备份之后的数据；只在确认范围后输入 `RESTORE`。恢复流程保留当前源码及服务器配置，不能当成代码版本回退。

## 7. 功能边界

本说明不涵盖首页改版、移动搜索入口、专题合集、AI生成简介或线上性能调优。服务器升级不会更新电脑上的桌面软件包、修改夸克登录环境或迁移 R2 图片存储。网站运营设置见 [系统设置与版本更新](系统设置与版本更新.md)。
