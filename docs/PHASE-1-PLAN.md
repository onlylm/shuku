# 阶段1实施计划（阶段0交付）

> 本文是阶段0的计划产物，不代表已经获得阶段1编码授权。必须先完成阶段0验收。

## 1. 阶段1目标

交付个人可运行的最小闭环：管理员能批量导入几百条书名和网盘链接，系统能识别百度/夸克、拦截重复与错链、人工审核后发布，访客能搜索详情并选择当前有效渠道。

## 2. 范围

包含：

- FastAPI、SQLAlchemy 2.x、MySQL 8、Alembic项目骨架。
- 超级管理员Session登录。
- 分类、资源、渠道、渠道资源、主备分享链接管理。
- XLSX/CSV导入、预览、匹配、错误报告和幂等提交。
- 首页、搜索、分类、单本详情、合集详情。
- `/go/{link_id}`、基础点击统计和无结果搜索记录。
- 手动与小批量链接检测。
- Sitemap、Robots、Canonical和基础结构化数据。
- 演示数据、测试、Docker Compose和README。

不包含：

- 自动下载资源。
- 无官方能力的平台自动上传或创建分享。
- Redis、Celery、大规模分布式任务。
- 普通用户账号、支付、评论、收藏和佣金计算。
- 复杂版权工单。

## 3. 开发小阶段

### 1A：工程与数据基础

- 初始化Git与Python 3.12项目。
- 配置Pydantic Settings、结构化日志、MySQL和测试数据库。
- 创建SQLAlchemy模型和首个Alembic迁移。
- 加载百度、夸克渠道种子数据。
- 完成唯一约束与模型测试。

验收：空数据库可以迁移；重复链接、渠道编码和分享ID被阻止。

### 1B：管理员认证与基础管理

- 超级管理员初始化命令。
- 安全密码哈希、Session、CSRF、登录限速。
- 资源、分类、渠道和链接的基础管理页面。
- 管理操作日志。

验收：未登录不能访问后台写操作；凭据不出现在日志。

### 1C：导入预览与防错

- openpyxl/CSV解析。
- 书名标准化与RapidFuzz候选匹配。
- 百度、夸克URL解析和规范化。
- 批次内/数据库重复、分享ID重复和跨资源冲突检查。
- 导入预览、单行决策、批量确认安全项、错误报告。
- 幂等提交和按批次回退本批新增项。

验收：标准测试表中所有重复和错链样例得到预期分类，阻断项无法提交。

### 1D：前台资源发现

- 首页、搜索、分类页。
- 单本和合集详情。
- 移动端响应式布局和空/错/加载状态。
- 零结果搜索聚合。

验收：390px无横向滚动，SEO标题唯一，草稿和隐藏资源不可访问。

### 1E：动态渠道与跳转

- 有效链接选择服务。
- 主备链接优先级。
- `/go`域名白名单、机器人过滤和最小化点击统计。
- 失效链接410状态页。
- 后台替换链接并即时检测。

验收：主链接失效后切换备用；全部失效时前台不显示获取按钮。

### 1F：SEO、部署与总验收

- Canonical、Open Graph、Book/CreativeWork与Breadcrumb结构化数据。
- Sitemap、Robots和noindex规则。
- Docker Compose、Nginx、`.env.example`和README。
- Playwright核心流程和视觉回归。
- 从本地Windows到Linux服务器的部署演练文档。

验收：Docker Compose可启动；迁移、核心测试和三视口页面测试通过。

## 4. 测试策略

- 单元测试：标题标准化、URL解析、链接选择、状态转换。
- 数据库测试：唯一约束、事务、软删除和迁移。
- 服务测试：导入匹配、错链拦截、替换链接、发布校验。
- 路由测试：认证、CSRF、SEO、404/410与 `/go`。
- 浏览器测试：登录、导入预览、资源编辑、搜索和移动端布局。

关键样例必须包含相同URL不同写法、相同分享ID、同链接绑定不同书、同名不同作者、验证码/限流和全部渠道失效。

## 5. 技术选择

- 后台普通CRUD可利用SQLAdmin底层能力；导入预览、资源编辑和检测中心使用定制Jinja页面，确保UI一致。
- XLSX使用openpyxl；匹配使用RapidFuzz；网络请求使用HTTPX；有限重试使用Tenacity。
- 定时任务在阶段1只保留任务表与手动触发；阶段3采用APScheduler稳定版。
- PDF元数据可使用pypdf；Calibre CLI作为后续可选独立工具。

## 6. 环境准备

当前检查发现项目尚未初始化Git，本机系统PATH暂未提供Node.js和Docker。阶段0静态原型不受影响；阶段1开始前需：

1. 安装或启用Python 3.12。
2. 安装Docker Desktop并验证Compose。
3. 正式初始化Git仓库和 `.gitignore`。
4. 创建仅含占位值的 `.env.example`。

Tailwind CDN仅用于阶段0视觉原型；阶段1上线资源使用固定版本的本地构建CSS。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 同名不同版本误合并 | 作者/出版社/年份联合判断，低置信度人工确认 |
| 同链接绑定不同书 | 全局URL哈希与分享ID唯一约束，跨资源冲突强阻断 |
| 网盘200响应但链接失效 | 平台文本规则与多次状态判断，不只看HTTP码 |
| 验证码/限流误判失效 | 保留原状态、延迟重试、降低频率 |
| 第三方接口不稳定 | 手工表格导入为始终可用的基础路径 |
| 本地/服务器路径不同 | 环境变量与容器卷挂载，不在代码写死盘符 |
| AI编造事实 | 事实字段只来自表格、文件元数据或人工确认 |
