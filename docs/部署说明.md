# 书库系统部署说明

这份教程面向第一次部署本项目的使用者。按顺序操作，可以将 GitHub 中的网站源码部署到自己的 Linux 服务器，并通过自己的 HTTPS 域名访问前台和管理后台。

每一步都按“输入什么 → 看到什么 → 接下来做什么 → 怎样判断成功”说明。已经部署好的网站不要重复从头安装，直接看后面的日常维护部分。

## 一、开始前准备什么

准备以下条件：

- 一台能够通过 SSH 登录的 Linux 服务器，账号为 root 或具有 sudo 权限。
- 本教程自动安装流程支持全新的 Ubuntu 22.04/24.04、Debian 12/13。
- 一个由自己管理的域名，以及服务器的公网 IPv4 地址。
- 服务器可以访问 GitHub、Docker 官方软件源、镜像仓库和 Python 软件源。
- 80、443 端口没有被其他网站占用，云平台安全组和系统防火墙允许外部访问这两个端口。保留自己的 SSH 管理端口，不要直接关闭整个防火墙。

如果服务器已经运行宝塔、Nginx、其他网站或其他 Docker 环境，请先确认端口及服务安排，不要为了安装本项目直接卸载现有服务。

网站运行依赖、数据库和 HTTPS 服务会由部署流程安装和启动，不需要事先安装 MySQL、Caddy 或 Windows 桌面整理软件。已有 Docker 的服务器还需要 Python 3.10+ 和 Compose 插件；脚本会检查并提示缺少的组件。

**示例约定：** 下文的 `books.example.com` 仅用于说明填写格式，必须换成自己的真实域名。它不是项目提供的公共访问地址。项目目录统一使用 `ebook-site`；如果自己更改目录名，后续命令也要对应修改。

**操作约定：** 命令一次复制一条，按回车执行，等待提示后再进行下一步。不要把终端提示符（例如 `root@server:~#`）一起复制，也不要把两次粘贴的命令连成一行。

## 二、先把域名指向服务器

在域名服务商的 DNS 管理页面，点击“添加记录”。

如果网站地址使用 `example.com`，填写：

| 配置项 | 应填写的内容 |
| --- | --- |
| 主机记录 | `@` |
| 记录类型 | `A` |
| 记录值 | 自己服务器的公网 IPv4 地址 |
| 解析线路 | 默认 |
| TTL | 保持平台默认值 |

如果网站地址使用 `books.example.com`，只把主机记录改为 `books`，其余相同。不要把整个网址或 `https://` 填进主机记录。

看到记录保存成功后，等待解析生效。`*` 泛解析不能替代主域名的 `@` 记录；主机记录含义可参阅 [DNSPod 官方说明](https://docs.dnspod.com/dns/help-name-zh/)。如果已经存在对应的记录，核对它是否指向正确服务器，不要盲目添加互相冲突的记录。

注意：

- 没有配置可用 IPv6 的服务器，不要为网站保留指向错误位置的 AAAA 记录。
- 如果使用 Cloudflare 代理，首次排查可先使用“仅 DNS”，确认源站 HTTPS 正常后再配置代理，详见 [进阶部署指南](Linux一键部署指南.md)。
- 本教程部署的是稍后填写的一个网站主机名；只添加 `www` 解析不会自动配置网站的 `www` 访问或跳转。

## 三、登录服务器，检查 Git

使用服务器提供的 SSH 终端或自己的 SSH 客户端登录。看到类似下面的提示符，表示已经可以输入命令：

```text
root@server:~#
```

普通 sudo 用户可能显示 `$` 而不是 `#`，不影响后面的操作。

**输入：**

```bash
git --version
```

**看到类似结果：**

```text
git version 2.x.x
```

表示 Git 已安装，进入下一节。实际版本号不要求与示例相同。

**如果看到 `git: command not found`：** 在上述支持的 Ubuntu/Debian 系统中，依次执行下面两条命令，每条执行结束后再输入下一条：

```bash
sudo apt-get update
```

```bash
sudo apt-get install -y git
```

安装完成后，再运行 `git --version` 确认。

非 root 用户首次使用 sudo 时，可能看到 `[sudo] password for ...:`。这里输入的是服务器登录账号的密码，不是网站密码；输入时不显示字符是正常现象，输入完按回车。

## 四、下载项目源码

**先输入：**

```bash
cd ~
```

执行成功通常没有额外输出，这是正常的。

**再输入：**

```bash
git clone https://github.com/onlylm/shuku.git ebook-site
```

**等待出现类似输出：**

```text
Cloning into 'ebook-site'...
Receiving objects: 100% ... done.
Resolving deltas: 100% ... done.
```

数字、速度和文件数量会随版本变化。最后重新出现可以输入命令的提示符，且没有 `fatal` 错误，表示下载完成。

**如果提示目录已存在：**

```text
fatal: destination path 'ebook-site' already exists and is not an empty directory.
```

不要删除该目录。若这是之前已经下载的本项目，直接进入下一节；若不确定目录用途，先检查，不要覆盖其他项目。已上线实例应使用后面的更新流程。

## 五、进入项目目录

**输入：**

```bash
cd ~/ebook-site
```

**再输入：**

```bash
ls deploy.sh
```

**正确结果：**

```text
deploy.sh
```

表示已经进入正确目录。接下来的部署和维护命令，都在这个目录执行。

如果提示找不到文件，先不要继续安装。检查上一节源码是否下载成功、目录名是否修改过。

## 六、启动部署，确认安装 Docker

**输入一次：**

```bash
sudo bash deploy.sh
```

**全新服务器可能看到：**

```text
尚未安装 Docker。安装会添加 Docker 官方软件源，不会修改防火墙。
是否在这台服务器安装？输入 y 继续 [y/N]：
```

**在这个提示后输入：**

```text
y
```

按回车。随后会出现软件下载和安装输出，等待程序继续，不要在安装过程中输入下一条部署命令。

**如果没有看到安装询问：** 服务器可能已经安装 Docker，脚本会直接检查环境并进入配置步骤。

**如果看到不支持当前系统、已有软件冲突或无法连接 Docker：** 说明环境检查未通过，先解决提示中的问题。脚本不会为了继续安装而自动卸载其他服务。不要忽略错误反复执行，也不要随意删除已有 Docker 目录。

## 七、按提示填写域名和网站名称

### 1. 填写网站域名

**看到：**

```text
正式网站域名（不带 https://，现在不填可按 Ctrl+C 退出）：
```

**输入自己的真实域名，格式例如：**

```text
books.example.com
```

按回车。请与第二节设置的 DNS 记录一致。

只填域名，不填 `https://`、`/admin/login`、端口或服务器 IP。上面的示例域名必须替换。网站域名与封面图片域名是两回事，这里填网站地址。

### 2. 填写网站名称

**看到：**

```text
网站名称 [书库]：
```

**例如输入：**

```text
我的书库
```

按回车。也可以什么都不输入，直接回车，使用默认名称“书库”。

### 3. 保存管理员密码

**接下来会看到类似：**

```text
配置已生成：/项目所在路径/ebook-site/deploy/.env
首次管理员：admin
首次密码：（此处是程序实际生成的随机密码）
正式配置检查通过；已有配置不会被重置。
```

此时不需要再输入内容。将终端中实际生成的密码保存到自己的密码管理器，不要复制括号里的示例文字作为密码。

不要公开包含密码的截图，也不要把 `deploy/.env` 上传到 GitHub。正式站点不使用本地演示账号的默认密码。

**再次部署时没有询问域名、也没有重新显示密码，是不是出错？** 不是。如果 `deploy/.env` 已经存在，脚本会复用已有配置，不重新生成数据库密码或网站编号。忘记管理员密码请使用第十二节的重置步骤，不要删除配置文件。

## 八、等待下载、构建和启动

配置通过后，会看到：

```text
正在构建网站；不会导入演示资源或读取本地开发数据库。
```

接下来不需要输入任何内容，只需等待。终端可能陆续出现这些关键词，具体排版会随 Docker 版本变化：

| 看到的内容 | 含义 | 需要做什么 |
| --- | --- | --- |
| `RUN apt-get ...`、`RUN pip install ...` | 正在安装网站依赖 | 等待 |
| `Image ebook-site-web Built` | 网站镜像已构建 | 继续等待，尚未部署完成 |
| `mysql:8.4 Pulling`、`caddy:2-alpine Pulling` | 正在下载数据库与 HTTPS 服务镜像 | 等待下载 |
| `Waiting`、`Starting` | 服务正在启动或等待依赖就绪 | 等待 |
| `Healthy` | 对应服务的健康检查通过 | 继续看最后的公网检查结果 |

首次安装需要下载依赖和镜像，耗时与服务器网络、硬盘及配置有关。单纯等待几分钟不表示安装失败；后续部署通常可以复用未变化的缓存。

安装过程中不要关闭终端、反复粘贴命令或主动中断。如果连续 5～10 分钟下载进度没有变化，或者出现 `ERROR`、`failed`、`timeout`，保存末尾错误信息并按第十五节排查。提供日志给维护者前，先遮住密码、令牌和其他敏感内容。

## 九、看到什么才算部署成功

服务启动后，脚本会检查公开 HTTPS 地址。**最后应看到类似：**

```text
容器已启动。正在核验 https://books.example.com 的有效证书和网站响应……
HTTPS、数据库、前台、后台登录页、robots 和 sitemap 均响应正常。
部署完成。网站：https://books.example.com  管理后台：https://books.example.com/admin/login
```

实际输出使用自己在第七节填写的域名。看到“部署完成”并返回终端提示符，才表示本次部署检查通过。

**如果看到下面这句，则还没有完成验收：**

```text
应用已启动，但公网 HTTPS 验证未通过，不能算部署完成。
```

此时不要删库或重装。按第十五节检查域名解析、80/443 端口和日志，修正后再运行 `sudo bash deploy.sh`。

## 十、打开网站并登录后台

**在电脑浏览器地址栏输入自己的网站地址，例如：**

```text
https://books.example.com
```

应该能看到网站首页。

**然后访问后台，例如：**

```text
https://books.example.com/admin/login
```

在登录页面填写：

| 登录项 | 应填写的内容 |
| --- | --- |
| 用户名 | `admin`，除非管理员另行修改过配置 |
| 密码 | 第七节在终端中生成并保存的随机密码 |

点击登录。进入后台后，网站基础部署完成。

不要用 `http://服务器IP:8000` 作为正式后台地址。正式部署只公开 80/443，后台登录需要使用配置好的 HTTPS 域名。

首次安装是空书库，只初始化管理员、基础分类和网盘渠道，不包含开发者的演示书籍、本地数据库或私人网盘数据。这是正常结果。

## 十一、部署完成后先验证一条资源

先不要批量导入大量书籍。使用一条自己有权发布的测试资源：

1. 在后台创建资源，填写书名、分类、来源说明等信息。
2. 添加这条资源对应的网盘分享链接，按需填写提取码。
3. 执行链接检测，检查渠道名称、链接状态和显示状态。
4. 明确发布资源，再到前台检查分类、详情和下载跳转。

网站部署完成不代表网盘授权、真实分享链接、封面存储或桌面工具也已经配置完成。正式部署默认关闭服务器云盘上传任务和自动链接巡检；Linux 服务器不能直接读取使用者电脑里的电子书文件。

如需接入 Cloudflare R2 封面、桌面整理工具或迁移已有书库，参阅 [进阶部署指南](Linux一键部署指南.md) 中的配置及数据说明，分别完成验收。

## 十二、忘记管理员密码怎么办

登录服务器，**先输入：**

```bash
cd ~/ebook-site
```

**再输入：**

```bash
sudo bash deploy.sh password
```

**看到：**

```text
管理员密码：
```

输入自己准备的新密码，按回车。输入过程中不显示字符，也不一定显示星号，这是正常现象。

建议使用至少 16 位的独立强密码并保存在密码管理器中。当前程序会拒绝不足 10 个字符的密码；如果出现“密码至少需要 10 个字符”，重新执行本节命令并输入更长的密码。

**成功时看到：**

```text
已重置管理员：admin
```

回到后台登录页，使用新密码登录。不要通过修改 `INITIAL_ADMIN_PASSWORD` 或删除数据库来重置已有管理员密码。

## 十三、日常检查与备份

下面是按需使用的操作，不需要每天全部执行。每次重新登录服务器后，先输入：

```bash
cd ~/ebook-site
```

### 1. 检查网站是否正常

**输入：**

```bash
sudo bash deploy.sh check
```

**正常情况下可以看到：**

```text
数据库与应用就绪
HTTPS、数据库、前台、后台登录页、robots 和 sitemap 均响应正常。
```

出现错误时不要直接重装，先看第十五节。

### 2. 查看服务状态

**输入：**

```bash
sudo bash deploy.sh status
```

**应看到：** 数据库 `db`、网站 `web`、HTTPS 服务 `caddy` 的状态列表。`Up` 表示运行中；数据库和网站应通过健康检查。若出现 `Exited`、`Restarting` 或 `unhealthy`，继续查看日志，而不是将它们当作部署成功。

### 3. 创建备份

**输入：**

```bash
sudo bash deploy.sh backup
```

**看到：**

```text
正在备份数据库、封面、运行数据和配置；网站会短暂停止写入。
```

等待结束。**成功时看到类似：**

```text
完整备份：/项目所在路径/ebook-site/backups/时间-随机编号（含敏感信息，请另存到安全位置）
```

记下实际备份目录，使用自己的 SFTP/文件管理工具将整个备份目录复制到服务器之外的安全位置。备份只保存在同一台服务器上，无法防范服务器丢失。

备份包含网站数据库、运行数据、本地上传封面和私密配置，不是加密文件，不要上传 GitHub。它不包含电脑原始电子书和 R2 中的远程图片。以 `.partial` 结尾的目录是未完成备份，不能用于自动恢复。

恢复会替换现有数据，属于高风险操作，不作为首次部署的必做步骤。需要恢复时，按 [进阶部署指南的备份与恢复章节](Linux一键部署指南.md) 操作，不要自行删除数据库或数据卷。

## 十四、后续怎样升级网站

只有需要更新网站程序时才执行本节。GitHub 上的文档更新不会自动重启或更新服务器，也不要求为了阅读文档重新部署。

先查看 [项目自动检查](https://github.com/onlylm/shuku/actions)，确认准备使用的代码版本检查通过。然后在服务器上依次输入：

```bash
cd ~/ebook-site
```

```bash
sudo bash deploy.sh update
```

**接下来会看到：** 备份、拉取更新、重新构建和启动、检查网站等输出。等待最终再次出现：

```text
部署完成。网站：https://books.example.com  管理后台：https://books.example.com/admin/login
```

实际输出为自己的域名。已有管理员密码不会因为正常升级而被重置；不要更改数据库密码、数据库名称或 `COMPOSE_PROJECT_NAME` 来“配合升级”。

**如果看到：**

```text
错误：服务器源码有未提交修改；请先保存，不自动覆盖。
```

说明服务器代码被修改过。停止更新，保留现场，联系维护者处理；不要使用强制重置或删目录的方式继续。

## 十五、常见提示与下一步操作

### 1. 提示 `deploy.shsudo: No such file or directory`

原因通常是把同一条命令连续粘贴了两次，导致文件名连成了 `deploy.shsudo`。

在已经返回的终端提示符后，重新只输入一行：

```bash
sudo bash deploy.sh
```

按一次回车即可。

### 2. 提示 `deploy.sh: No such file or directory`

先输入：

```bash
cd ~/ebook-site
```

再输入：

```bash
ls deploy.sh
```

只有看到 `deploy.sh` 后，才继续部署。如果目录名或安装位置不同，应进入实际的项目根目录；找不到目录时检查第四节是否下载成功，不要盲目删除重建。

### 3. 提示“已有部署或备份操作正在进行”

说明同一个项目已有维护操作占用锁。先查看原终端，等待该操作结束；不要同时开多个部署命令，也不要删除锁文件强行继续。

### 4. 下载很慢或长时间停留在 `Pulling`

先看下载字节数和层进度是否继续变化。首次下载较慢不一定是错误。

若明确出现网络超时、连接失败或镜像下载错误，记录末尾报错，检查服务器访问镜像仓库的网络。命令已经失败退出后，解决网络问题，再执行：

```bash
sudo bash deploy.sh
```

不要为了加速把账号令牌交给不可信镜像服务，也不要在运行中的同一终端插入其他命令。

### 5. 公网 HTTPS 检查失败

确认部署命令已经结束后，**输入：**

```bash
sudo bash deploy.sh logs
```

查看最近日志，并依次检查：

- 域名是否填错、是否带了网址前缀或路径。
- 正确的 `@` 或子域名 A 记录是否指向自己的服务器。
- 是否存在错误的 AAAA 记录。
- 云平台安全组和系统防火墙是否允许 80/443。
- 是否有另一个网站占用了 80/443。
- 若启用了 Cloudflare 代理，源站及代理 HTTPS 配置是否一致。

修正问题后，再执行 `sudo bash deploy.sh`，直到看到“部署完成”。脚本会保留已有配置和管理员，不需要删库。

### 6. 显示密码输入提示，但键盘输入没有回显

sudo 密码和管理员新密码可能都不显示字符。正常输入后按回车即可，不要因为没有星号就把密码再次输入成另一条命令。

### 7. 网站打开了，但前台没有图书

首次部署是空库，不是自动导入开发者的书库。按第十一节录入自己的测试资源，并确认发布状态、分类和可用链接。电脑上的数据不会自动变成服务器上的 MySQL 数据。

### 8. 后台登录失败

先确认使用的是自己配置的 HTTPS 域名和 `/admin/login` 路径，再确认使用正式部署生成的密码。仍无法登录时按第十二节重置，不要使用本地演示密码反复尝试。

### 9. 遇到本教程没有列出的错误

保留命令最后的错误信息，说明系统版本、执行到哪一步、服务状态，再向维护者反馈。日志和截图中的密码、令牌、邮箱等敏感信息应先打码。

不要公开 `deploy/.env`，不要开启包含敏感参数的调试输出，也不要执行删库、删除数据卷或强制覆盖源码的命令来“重装”。

## 十六、文件与数据放在哪里

以下路径都以服务器项目目录 `ebook-site` 为起点：

| 路径或位置 | 用途 | 注意事项 |
| --- | --- | --- |
| `deploy.sh` | 部署和维护入口 | 后续维护仍从项目根目录运行 |
| `deploy/.env` | 本站域名、名称、随机密码等私密配置 | 自动生成，禁止上传 GitHub |
| `deploy/.env.example` | 配置字段示例 | 可以公开，不含真实密码 |
| `backups/` | 备份目录 | 包含敏感数据，需要异地保存 |
| Docker 数据卷 | 网站数据库、运行数据、本地封面、HTTPS 证书 | 不是电脑上的 SQLite 书库，不要删除数据卷 |

完整配置项、已有环境适配、数据库迁移和灾难恢复说明见 [Linux 一键部署指南](Linux一键部署指南.md)。本教程负责网站部署，不代表桌面整理软件或每个网盘连接器已经完成真实账号验收。
